# Project instructions

Before making changes in this project, read `PROJECT_MEMORY.md` and `PHASE_PLAN.md`.

- Work only on the currently agreed phase and keep later-phase features deferred unless the user changes scope.
- Update `PHASE_PLAN.md` when implementation status, completed work, remaining work, or phase scope changes. Record meaningful changes in its dated change log.
- Update `PROJECT_MEMORY.md` when a durable product, workflow, design, architecture, or technology decision changes.
- When code behavior, data models, APIs, setup steps, or tests change, update the relevant phase notes so the docs match the implementation.
- Verify documentation claims against actual project files before marking work complete.
- At the end of a work session, leave a clear current status and next step in `PHASE_PLAN.md`.
- Do not start a new phase or expand scope without discussing feasibility and phase acceptance criteria with the user.

The original product specification is `AI_Engineering_Canvas_Project_Spec.pdf`. The project docs preserve its intent and current decisions; they do not replace source code as evidence of implemented behavior.
